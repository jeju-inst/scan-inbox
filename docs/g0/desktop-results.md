### 한글 OCR 품질과 큰 제목줄 (총괄 요청 별도 표기)

합성 문서의 제목은 22pt(본문 11pt의 2배) 한 줄입니다. OCR 텍스트 층에서 제목줄을 확인한 결과:

- **제목줄이 통째로 사라진 사례: 기본 옵션에서는 0건.** 단, `--oversample 300` 을 준 재시험에서는 회전·빈 페이지 문서의 제목 "현장 점검 결과 보고" 줄이 **통째로 누락**됐음(같은 옵션으로 다른 문서 1건은 개선). 옵션에 따라 제목줄 인식이 흔들리는 불안정이 있음.
- **제목줄 글자 오인식 2건/스캔 16건**: "현장 점검 결과 보고" → `장[ 엔 ox 검결과보고`(회전·빈 페이지 문서 1쪽), "긴 경로 시험 문서" → `긴경로시 9! 문서`('험' 소실, 긴 한글 경로 문서). 본문 11pt 줄에서도 `가상회의실 A`→`가상회의실 4`, `2026년 7월 14일`→`202614 9 월 108`처럼 오독이 있음.
- **제목줄 분할·순서 뒤섞임 1건**: "2026년도 예시 사업 추진계획" 이 문서번호 줄을 사이에 두고 두 조각(`2026 년도예시사업` / `추진계획`)으로 나와 텍스트 순서상 연속하지 않음(옵션 `--oversample 300` 에서는 한 줄로 정상 인식).
- **띄어쓰기**: 한글 단어 사이 공백이 거의 사라지고(`연구용역착수회의결과`) 일부 문자 사이에 U+0000 이 끼는 경우가 있음(영문 병기 줄). 이름 규칙에서 공백 복원이 별도로 필요함.
- 영문 스캔 제목 2건은 모두 정확. 한영 혼합 제목은 2건 모두 OCR 층에 포함(NUL 문자 제거 후). 한글 스캔 제목은 위 오인식·분할 사례를 제외하면 공백 무시 완전 일치.
- 제약: `tessdata_fast` 모델, 150 dpi, 합성 단일 글꼴 기준임. `tessdata_best`·해상도·전처리 옵션 비교는 시험하지 않았음(미시험).

- **v1.8.0 arm dmg**: 내려받아 읽기 전용 마운트로 확인. 앱 번들 120 MB, 최소 macOS 11.0, **ad-hoc 서명(TeamIdentifier 없음)·공증 없음**(`spctl` 거부). 즉 일반 사용자는 Gatekeeper 경고를 거쳐야 실행 가능. 이 시험에서는 quarantine 속성이 없는 복사본이라 경고 화면 자체는 재현하지 못함.
- **헤드리스 실행 불가(1.8.0)**: 최신 main 문서의 `--headless` CLI 계약(`--review-only`·`--auto-apply`·status JSON)이 1.8.0 바이너리에는 없음(문자열 검색 0건). 따라서 CLI 로 합성 코퍼스를 돌릴 수 없음.
- **기동 확인**: 앱을 약 30초 실행했을 때 열린 네트워크 소켓 없음(`lsof` 시점 스냅샷 2회, 단발 연결은 놓쳤을 수 있음). 최초 실행 상태이며 모델 미선택. 문서·모델 분석은 실행하지 않음. 원격 모델 키는 입력·활성화하지 않음. 공식 README 상 로컬 모델은 외부 전송이 없고 원격 모델(OpenAI·Gemini·사용자 지정 API)은 사용자가 키를 넣을 때만 사용한다고 기술하나, 이번에 코드·패킷으로 검증하지는 않음.
- **소스 빌드(v1.9.2) 중단**: 필요한 `brew install qt cmake jsoncpp fmt spdlog mediainfo curl` 을 `--dry-run` 한 결과 신규 설치 외에 기존 의존성(protobuf, abseil, glib, harfbuzz, cairo, curl 계열 등) 십여 건을 **업그레이드**하게 되어 사용자 Homebrew 전역을 바꿈. "시스템 변경은 필요한 최소만" 원칙에 맞지 않아 실행하지 않고 중단함. 별도 Homebrew 접두사나 conda-forge 격리 빌드는 시도하지 않음(미시험, 별도 승인·시간 필요).
- **모델 다운로드**: 시험하지 않음. 문서 기준 기본 로컬 모델은 Gemma 3 4B IT(GGUF)이며 크기 확인은 이번 범위에서 하지 않음(미시험). 필요 시 사용자 결정 후 진행.
- **미확인 항목(전부 미시험)**: 스캔 이미지 PDF 한국어 인식(문서 기준 PDF 추출은 PDFium 텍스트 추출이라 OCR 텍스트층이 없으면 내용을 못 읽을 가능성이 큼 — 사전에 OCRmyPDF 처리본을 넣어야 할 수 있음), 폴더 감시, 완료함·원본 보존 정책, Undo(README 는 "Edit → Undo last run" 기재), 입력 정리.
- **라이선스**: AGPL-3.0. MIT 저장소로 코드를 가져오지 않음. 동반 시험에서도 코드 복사 없음.

## 전송·민감정보·라이선스 검토 결과

- 합성 자료만 사용, 외부 전송 없음. 의도적으로 원격 모델·API 키를 쓰지 않음.
- organize(MIT)·OCRmyPDF(MPL-2.0)·Tesseract(Apache-2.0)는 로컬 실행. Ghostscript(AGPL)·qpdf 는 시스템 기존 설치를 호출만 했고 재배포 의무는 판단하지 않음(별도 검토 필요).
- 위 결과·로그에는 합성 파일 정보만 있고 실경로·실문서 발췌는 없음.

## 채택/설정 보완/부분 확장/신규 개발 권고와 근거

1. **OCR 엔진: OCRmyPDF + Tesseract kor+eng 는 부품으로 채택 가능(설정 보완).** kor 언어팩 배치·`configs` 포함·`--skip-text`·PDF/A 출력 변경 인지가 필요함. 단 큰 제목줄 오인식·옵션 민감성과 `/Rotate` 쪽 미인식은 실문서 표본으로 재평가하고 `tessdata_best`·해상도·전처리 옵션 비교가 필요함.
2. **organize 단독으로는 요구 충족 불가 → 부분 확장 또는 신규 개발 쪽.** 부족한 것은 정확히 PLAN.md 의 경계 기능임: 제목 신뢰도·승인 단계, 원본 보존과 실행 기록(ledger), 완료된 입력만 정리, Undo, 안전한 파일명 처리. 이를 접합 코드로 채우면 사실상 조율 계층을 새로 쓰는 것이며, 그 경우 organize 는 이동·충돌 회피 부품 이상의 역할이 작음.
3. **AI File Sorter 는 G0 판정 보류.** macOS 배포 부재(1.9.2)와 헤드리스 부재(1.8.0) 때문에 이번 환경에서 시험 불가. 판정하려면 (a) Homebrew 전역 변경 승인 또는 격리 빌드 환경, (b) 로컬 모델 다운로드 승인, (c) GUI 조작 시험 또는 최신 소스의 헤드리스 빌드가 필요함.
4. `reconcile`·`snapshot` 하네스는 실제 도구 출력에도 동작함을 확인함. 제안: reconcile 에 "검토 대상(`expected_outcome=review`)이 자동 완료됨" 위반 검사를 추가하면 위 오완료 2건을 하네스가 직접 잡을 수 있음(이번에는 `title_accuracy.py` 로 별도 확인).
