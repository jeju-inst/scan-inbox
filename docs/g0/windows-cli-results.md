# G0 시험 결과: 구독 LLM CLI 어댑터의 Windows 네이티브 동작

시험일: 2026-11-05. 시험자: worker2(claude/scan-inbox-worker-2). [llm-cli-adapters.md](llm-cli-adapters.md) §5 Windows 체크리스트를 따르며, 그 문서 §2의 표 형식(`충족 / 설정 필요 / 불가·미충족 / 미시험 / 미확인`)으로 기록합니다.

이 문서는 **Windows 11 x64 시험 머신(비관리자 계정, 원격 셸)** 에서 한 **소표본 사전 시험**입니다. CLI당 모델 호출은 5회 이내로 제한했고(Claude Code 5회, Codex 5회, agy 0회), 입력은 완전 가상 합성 텍스트뿐입니다. 사용자 파일·실제 스캔 폴더는 열지 않았습니다. 구독 로그인 경로만 썼고 API 키 환경변수는 쓰지 않았으며 시험 머신에 해당 변수가 설정돼 있지 않음을 확인했습니다. **로그인·설치는 하지 않았습니다.**

## 대상 버전과 설치·로그인 상태

| 항목 | Claude Code | OpenAI Codex | Antigravity (`agy`) |
| --- | --- | --- | --- |
| 설치 | 설치됨. 네이티브 `claude.exe` (사용자 폴더 `.local\bin`) | 설치됨. npm 전역 패키지의 **셸 shim**(`codex.cmd`·`codex.ps1`) → `node.exe` → 네이티브 `codex.exe` | 설치됨. `agy.exe` 가 두 곳(사용자 앱 폴더와 WinGet Links)에서 검색됨 |
| 버전 | 2.1.312 | codex-cli 0.161.0 | 1.4.10 |
| 로그인 | `claude auth status --json` → `loggedIn: true`, 구독형(claude.ai 로그인). 원격 셸 세션에서도 읽힘 | `codex login status` → `Logged in using ChatGPT` | **로그인 안 됨**: `agy models` → 종료코드 1, `Please sign in to view available models.` / 토큰 파일 없음 |

- 버전이 macOS 조사 때(2.1.318 / 0.160.0 / 1.5.0)와 **다릅니다.** Claude Code·agy 는 한 단계 낮고 Codex 는 높습니다. 같은 플래그가 두 버전 사이에서 동일하게 동작하는지는 이번에 확인하지 못했습니다.
- **agy 는 로그인이 필요해 모델 호출 시험을 하지 못했습니다.** 설치·로그인은 사용자 승인이 필요한 사항이라 하지 않았으며 총괄에게 알립니다. 아래 agy 관찰은 모두 **로그아웃 상태에서의 동작**입니다.
- 이 머신의 환경: Windows 11 Home x64, 한국어 로캘, `PYTHONUTF8=1` 설정됨, `LongPathsEnabled=0`. 시험 드라이버는 시스템 Python 3.12 의 `subprocess` 로 인자 배열(리스트)로 실행했고(앱의 실행 방식을 모사), 입력은 UTF-8 바이트로 stdin 에 직접 썼습니다.

## 체크리스트(§5) 항목별 결과

1. **설치 경로·PATH**: `claude.exe`, `codex.cmd`(+`.ps1`, 확장자 없는 shim), `agy.exe` 가 모두 PATH 에서 검색됨. Codex 는 **네이티브 `codex.exe` 가 npm 패키지 깊은 폴더**(`node_modules\@openai\codex\...\vendor\...\bin`)에 따로 있고 PATH 에는 `.cmd` 만 노출됩니다. 앱이 `codex` 를 이름으로 실행하면 이 shim을 거칩니다.
2. **콘솔 인코딩·stdin**: 시스템 `PYTHONUTF8=1` 환경에서 UTF-8 바이트를 stdin 으로 직접 전달하는 방식은 한글 입력·출력 모두 정상(Claude Code·Codex). **PowerShell 파이프(`type file | claude -p`, `Get-Content | ...`)·`cmd.exe` 파이프의 인코딩은 미시험**입니다. 원격 셸의 콘솔 출력이 `cp949` 로 깨져 보이는 것은 표시 문제였고 CLI 입출력과 무관했습니다.
3. **인자 이스케이프**: Claude Code 는 **인라인 JSON 스키마**와 빈 문자열 인자(`--tools ""`)가 손상 없이 전달됨. 큰따옴표·작은따옴표·`& | ^ %VAR% ( )`·`C:\a b\` 포함 문자열도 `claude.exe` 직접 실행에서는 그대로 왕복했습니다. Codex 는 `.cmd` shim을 거치며 **같은 문자열에서 `%PATH%` 가 cmd.exe 에 의해 치환**되어 프롬프트에 머신의 실제 PATH 문자열이 들어갔고 모델 응답에도 노출됐습니다(나머지 문자는 인자가 큰따옴표로 감싸져 보존됨). 즉 **셸 shim을 거치는 실행은 문서 내용이 인자에 들어가면 환경변수 값이 외부 서비스로 나갈 수 있습니다.** 문서·발췌는 인자 대신 stdin 으로 넘기고, 가능하면 shim이 아닌 네이티브 실행 파일을 직접 실행해야 합니다. **`codex.exe` 직접 실행에서 이 현상이 없는지는 시험하지 않았습니다(미시험).**
4. **자격증명**: Claude Code·Codex 로그인 상태를 Windows 에서 읽을 수 있습니다. 시험은 원격 셸 세션이었고 로그인 정보가 그 세션에서 인식됐습니다(저장소 종류·잠금 영향은 확인하지 않음). agy 는 로그아웃.
5. **타임아웃·트리 종료**: 위 표 5행. 핵심은 **Codex 의 3단 구조(`cmd.exe` → `node.exe` → `codex.exe`)에서 부모만 끄면 자식이 남는다는 점**이고, 앱은 Windows 에서 작업 객체(Job Object) 또는 `taskkill /T /F`(대상 PID 가 살아 있을 때 트리 종료)로 끝내야 합니다. 시험 후 이 시험이 만든 고아는 모두 종료했고, 시험 전부터 있던 다른 세션의 프로세스는 건드리지 않았습니다. Claude Code 는 이번 시험(도구 비활성) 범위에서는 단일 프로세스였습니다. **도구·셸을 켠 실행에서의 자식 프로세스는 미시험**입니다. 종료코드는 `Popen.kill` 후 모두 1 이었으며 정상·오류 종료코드의 의미 구분은 시험하지 않았습니다.
6. **임시 격리 디렉터리**: 공백과 한글이 든 작업 폴더(사용자 폴더 아래 `공백 경로 시험`)에서 Claude Code·Codex 가 정상 실행됐습니다. `%TEMP%` 아래 경로와 260자 초과 경로는 이 시험에서 쓰지 않았습니다(미시험).

## 권고와 다음 단계

- **Claude Code**: Windows 에서 `claude.exe` 직접 실행으로 비대화형·한글·긴 입력·구조화 출력·인증 판별이 모두 동작했습니다. 남은 시험: 전역 MCP 차단 효과, 도구를 켠 실행의 프로세스 트리, 로컬 기록 보존, PowerShell/cmd 파이프.
- **Codex**: 실행 인터페이스는 동작하나 **npm 셸 shim 경유는 인자 치환·고아 프로세스 문제가 있어** 어댑터는 네이티브 `codex.exe` 를 직접 찾아 실행하거나(경로 탐색·버전 변동 대응 필요) 입력을 stdin 으로만 넘기고 트리 종료를 구현해야 합니다. `-s read-only` 의 읽기 차단 여부는 Windows 에서 `READ_FAILED` 였지만 원인 미확인이라 **격리 보장으로 간주하지 않습니다.**
- **agy**: 시험하지 못했습니다. **사용자 승인 후 구독 로그인**을 한 다음 같은 시험(A〜E)을 하면 됩니다. 로그아웃 상태에서 `--print "<프롬프트>"` 가 `--print-timeout` 과 무관하게 멈추는 점은 어댑터가 부모 쪽 타임아웃과 트리 종료를 따로 가져야 한다는 근거입니다.
- **공통**: 모델 호출 결과는 표본 1회씩이라 통계적 의미가 없으며, 위 판정은 동작 확인 수준입니다. 구독 약관상 허용 여부(7행)는 이번 범위 밖입니다.

## 시험 전후 시스템 변경 내역과 정리

- 시험 머신에 설치·로그인·설정 변경을 하지 않았습니다. 시험용으로 사용자 폴더 아래에 새 작업 폴더와 스크립트 2개를 만들었다가 **모두 삭제**했습니다(삭제 확인). 전역 PATH·레지스트리는 변경하지 않았습니다.
- Claude Code 는 `--no-session-persistence`, Codex 는 `--ephemeral` 로 호출했으나 **디스크 기록이 실제로 남지 않았는지는 확인하지 않았습니다.** 두 CLI 의 호출 이력은 해당 구독 계정의 사용량에는 반영됩니다(Claude Code 5회, Codex 5회).
- Codex 시험 B 에서 이 머신의 **PATH 문자열이 모델 요청·응답에 포함**되었습니다(shim의 `%PATH%` 치환). 합성 시험이었으며 이 문서에는 그 내용을 기록하지 않았습니다.
- 시험 머신에는 시험 전부터 다른 세션의 Codex 관련 프로세스가 떠 있었고 건드리지 않았습니다. 전원·재부팅 명령은 실행하지 않았습니다.
