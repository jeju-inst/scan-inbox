# 파일럿·인수 기준

아래는 **실행 전 계획**이며 통과 결과가 아닙니다. 실제 스캔 폴더에서는 아직 아무 파일도 열람·변경하지 않았습니다. 비공개 사전 조사에서는 지정된 입력 후보 폴더가 존재하고 PDF 적재분이 있음을 메타데이터로 확인했습니다. 실제 경로·파일명·수량·본문은 이 공개 저장소에 기록하지 않습니다.

## 단계

1. 합성 문서: 실제 인물·계좌·문서를 익명화해 만드는 대신 완전히 가상인 문서를 새로 만듭니다. 본문 제목이 있는 스캔, 제목 없는 서식, 영문·한영 혼합, 기존 텍스트 PDF, 혼합 PDF, 회전·빈 페이지, 다중 문서 묶음, 이름 충돌을 포함합니다.
2. 엔진·OSS 비교: 버전·커밋·OS·CPU·엔진·언어팩·옵션·모델 및 외부 전송 여부를 기록합니다. 로컬 경로·모델 응답·실문서 발췌를 공개 보고서에 넣지 않습니다.
3. 대표 복사본: 사용자 동의 후 비공개 테스트 공간에 한정해 원본 바이트와 manifest를 보관하고 복사본에서만 수행합니다. 원본 스캔 폴더는 그대로 둡니다.
4. 첫 수동 실행: 계획 미리보기→사용자 승인→최종본 배치→원본 복구를 확인합니다.
5. 적재분 처리: 성공·보류·실패 건수를 원래 목록과 대조합니다. `완료 + 보류 + 실패 + 미착수 = 입력 등록 건수`를 프로그램으로 검증합니다. 실물 문서 수와 파일 수는 구분합니다.
6. 제한 운영: 복구 시험 통과·사용자 승인 후 실제 입력 폴더에서 수동 처리부터 시작합니다. 감시·자동 승인은 별도 켭니다.

## 필수 통과 조건

- 무변경 preview에서 파일명·본문·mtime·위치가 전후 동일합니다. 앱 내부 캐시는 허용하되 입력은 바꾸지 않습니다.
- 원본 바이트 일치 100%, 묵시적 덮어쓰기·소실 0건. 완료된 입력 각각에 원본과 최종 경로·해시·처리 결과가 있습니다.
- 완료 파일만 입력에서 사라집니다. 검토·실패 건은 입력에 남고 이유가 보입니다. OCR 선택 실패를 자동 성공으로 바꾸지 않습니다.
- 합성 제목 정확도·분류 정확도는 사전에 정한 정답과 검토자 기준으로 평가합니다. 제안 초기 목표는 제목 승인 가능 비율 90% 이상, 자동 이동 규칙 precision 98% 이상이나 소규모 표본으로 일반 성능을 보장하지 않습니다. 초기 파일럿의 분류 이동은 전건 승인합니다.
- OCR는 선택 언어 텍스트 검색, 페이지 수 보존, 표본 페이지 육안 대조로 검증합니다. 이미지 PDF에 읽을 수 없는 텍스트층만 넣고 성공이라 하지 않습니다. 소요 시간·메모리·용량 변화도 기록합니다.
- 날짜가 없거나 애매한 문서에서 문서 날짜를 조작하지 않습니다. OCR 오류·다중 문서·제목 불명은 검토 대상으로 드러납니다.
- 중복 이벤트, 앱 재실행, 처리 도중 강제 종료, 원본 보관 후 장애, 최종 배치 후 입력 정리 전 장애, DB commit 장애를 주입해 중복 최종본·입력 손실 없이 복구합니다.
- 작성 중 파일, 잠긴 파일, 디스크 부족, 권한 거절, 암호화·서명·손상 PDF, 네트워크 단절, 긴 한글 경로, NFC/NFD·대소문자 충돌, 서로 다른 볼륨을 시험합니다.
- Undo는 입력 복구와 실제 해시를 확인합니다. 최종본이 이후 수정됐거나 원래 경로가 사용 중이면 타 파일을 지우지 않고 충돌로 멈춥니다.
- 소스와 완료 폴더가 겹치거나 symlink/junction으로 루트를 탈출하는 구성은 거절됩니다. 문서 속 명령문·악성 파일명으로 외부 명령 실행이나 범위 밖 이동이 발생하지 않습니다.
- 기본 모드에서 네트워크 전송 없음과 원격 로깅 비활성을 확인합니다. 외부 AI 기능은 사용자 동의 전 호출되지 않아야 합니다.
- Windows 깨끗한 사용자 환경과 macOS의 실제 설치·실행·제거를 각각 시험합니다. 서명·공증 여부 및 보안 경고를 기록합니다. CI green을 설치 완료로 대신하지 않습니다.
